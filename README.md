# mesh-repair-studio

**一句话承诺**：一个破损三角网格（顶点裂缝 + 断缝）的"焊接修复"工作台——只用一个容差 ε 把一个非水密、欧拉 χ 破损的网格还原到水密、χ=0 的环面，修复在 node 里可复算、可计时，且在浏览器拖动同样的 ε 时与 node **逐位一致**。

**对照基线**（仓库内可跑）：朴素全对偶 O(n²) 顶点焊接 `baseline/naive-weld.mjs`。同一份 27,063 顶点 / 48,400 三角的破损环面网格上：

- 空间哈希焊接 **中位 47.3 ms**（7 样本，冷启动 66.2 ms）
- 朴素全对偶焊接 **中位 1790.2 ms**（7 样本）
- **加速 37.8×**，且两种算法输出逐位一致（`weldAgree` 在同一闭包上成立）
- ε≥最大分裂距时 2,863 个副本全部焊回，网格恢复水密、`χ = V−E+F = 0`（单孔环面），连通分量 = 1

> `Upstream: none`
> 原创工具轮次，无上游修复对象；算法为教科书级，本仓库的新意全在验证维度（见「本轮创新」）。

## 怎么跑

一条命令还原全部示例数据 + 行为断言（G4 的真断言）：

```bash
node bench/verify.mjs          # 若 data/ 不在：先 npm/node 生成 data
# 或从零开始：
node tools/gen-sample.mjs      # 生成 data/damaged-mesh.json + data/reference-scan.json
node bench/verify.mjs          # 10 项行为断言，全过 exit 0
node bench/bench.mjs           # 计时，写 bench/result.json（加速比 ~37.8×）
node baseline/naive-weld.mjs   # 复现朴素基线耗时
```

浏览器（交互 + 双端复算）：

```bash
python3 -m http.server 4173 &   # 打开 http://localhost:4173
```

拖动右侧 ε 滑块：three.js 用同一 `src/core.mjs` 的 `spatialHashWeld` 现场重建焊后网格
（去重、剔除退化三角），并实时显示 `uniqueVerts/边界/水密/χ`；结果与 node 预烘焙
的 `data/reference-scan.json` 比对，一致时显示绿色 ✓。

## 本轮创新

**新在哪**：把"网格修复（weld）"从离线脚本抬成一个**交互式 ε 扫描参数器**——用户拖动焊接容差 ε，
three.js 现场用同一 core 重算焊后拓扑，屏幕上的 `uniqueVerts/χ/水密` 数字**逐位等同**于
node 预烘焙的 `reference-scan.json`（"所见即所验"）。这不是新算法（教科书 weld），而是首次把
"空间哈希复杂度对照 + 双端位级一致 + 交互扫描"三者焊在一起，让修复结果在浏览器里可被 node 复验。
此前 3D 仓库里做过点云拾取/求交/等值面的加速，但**没有**"容差参数扫描 + 双端复算"合体；
昨晚 repos 明确点名这是本方向今日缺口。档位 **B**。

**和谁不一样 / 凭什么以前做不到**：与 QEM 减面、曲面求交预过滤等"单个加速数字"的仓库不同，
本仓库把验证从"跑一次出个数"升级为"任意 ε 拖动都复现同一份确定性参考"，把浏览器当成了
一个可验证的 node 复算前端。确定性来自固定种子 + 纯函数生成（两次跑 bytes 相同）。

## 已知限制

- 只处理"顶点分裂"型破损（副本顶点被 <ε 位移），不修 pinholes/洞、不重新三角剖分边界；
  破洞（真实缺三角）不在本版本范围内。
- 修复 ε 共享单一阈值；若破损位移分布极宽，单 ε 无法同时焊小缝又不错焊大真缝。
- 环形数据证明 χ=0 与双端一致；任意属网格需逐个换生成参数验证。
- 三类手柄一档 ε；未做修补（fill-hole）只做焊接。

## 测试

`bench/verify.mjs` 的行为断言（真跑，非只测语法）：确定性生成（两跑 bytes 一致）、
ε 极小 → 非水密不焊接、ε 足够大 → 全部副本焊回 + 水密 + χ=0 + 连通=1、空间哈希与朴素
位级一致、扫描 uniqueVerts 单调不增、体积在焊接下不变。
